# Spec-Driven Development

Use this workflow when building new features or making significant changes.

## Steps

1. **Interview** — Ask questions to clarify requirements, constraints, and scope
2. **Spec** — Write SPEC.md documenting the what and why
3. **Plan** — Write PLAN.md with architecture, data flow, component tree, route design
4. **Tests** — Write tests first (all red)
5. **Code** — Write minimum code to pass tests
6. **Verify** — Run tests, lint, and typecheck (all green)
7. **Review** — Review code for quality, patterns, security
8. **Loop** — Iterate steps 4-7 until review passes
9. **Docs** — Update documentation if needed
